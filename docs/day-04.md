### 3. HTTP 流式入口：45 分钟

新增 POST /meeting-summary/stream；请求体与普通接口一致：

```json
{"text":"小王周五前完成模型调用，前端展示方案尚未确定。"}
```

为避免整段 JSON 必须收齐才能解析，本日使用 NDJSON：每行一个独立 JSON 对象，以换行结束。Content-Type 为 application/x-ndjson；UTF-8 编码。这是本服务的协议，不是直接透传供应商的 SSE 协议。

正常结果示意：

```json
{"type":"delta","text":"摘要："}
{"type":"delta","text":"完成模型调用。"}
{"type":"done"}
```

生成中途失败示意：

```json
{"type":"delta","text":"摘要："}
{"type":"error","message":"模型服务暂时不可用"}
```

验收合同：

| 场景 | 必须观察到的结果 |
| --- | --- |
| 非法输入 | 422；模型不调用 |
| 有效输入、产生文本并正常结束 | 200；若干 delta；最后且仅有一个 done |
| 上游没有产生可用文本 | error；不输出 done |
| 上游开始迭代前失败或输出一部分后抛出异常 | 一个 error 后结束；不输出 done；不暴露密钥、原始异常或堆栈 |

本日约定：输入校验在开始流式响应前完成；上游调用与迭代放在响应生成器里，失败通过 error 行表达。因此模型失败时 HTTP 状态可能仍为 200。响应头发出后不能再改成 502，客户端必须检查终止事件；done 才表示正常完成。普通接口的 502 合同继续保留。

先使用同步生成器配合 StreamingResponse，继续复用同步 SDK。StreamingResponse 支持普通生成器，不必为此先迁移整个应用到异步 SDK。仅在上游调用和迭代的边界统一处理异常，不吞掉全部应用错误。
