## 一、项目任务：120 分钟

### 1. 明确调用链：25 分钟

调用链：用户程序 → 你的 FastAPI 服务 → Gemini → 你的服务 → 用户程序。

先画出两段 HTTP 请求，标明各段的客户端、服务端、输入和输出。区别用户传给你的请求与 SDK 传给 Google 的请求。

建议新建 app/api.py 作为 Web 入口，避免把现有 CLI 入口强行改成服务入口。启动方式：


其中 app.api 是模块位置，最后的 app 是你定义的 FastAPI 实例。启动后用 http://127.0.0.1:8000/docs 提交请求；不需要开发前端。

### 2. 实现接口：55 分钟

接口：POST /meeting-summary。客户端请求头 Content-Type 为 application/json，正文如下：

```json
{"text": "小王周五前完成模型调用，前端展示方案尚未确定。"}
```

成功响应：HTTP 200，JSON 正文包含 summary 字符串。

```json
{"summary": "这里是模型实际返回的摘要、待办事项与待确认事项"}
```

summary 保留 Day 2 的整理要求，不要求把待办解析成结构化字段。结果不能声称任务已经写入系统。

接口合同：

| 条件 | 必须观察到的结果 |
| --- | --- |
| 合法非空文本，模型返回有效文字 | 200；summary 为返回的实际文字；调用一次 generate |
| 缺少 text，或 text 是空字符串、纯空白 | 422；不创建模型客户端、不调用模型 |
| generate 返回 FAILED 或 UNKNOWN | 502；detail 为简短、可理解的失败提示 |
| 返回 SUCCESS 但 content 是 None、空字符串或纯空白 | 502；不能返回空摘要或把它视为成功 |

422 表示客户端提交的数据不符合约定；502 表示你的服务未能从上游模型服务取得可用结果。HTTP 接口通过状态码表达本次请求失败，不能照搬 CLI 的 SystemExit；一次请求失败不应该主动退出整个服务进程。

输入用 Pydantic 模型校验，包含去除首尾空白和非空约束。响应也用一个简单模型表达。具体函数和类名自行选择。

现有 Gemini 调用是同步调用，因此本日接口先用 def。不要只把它包进 async def 就认为变成异步调用。网络异常统一捕获和专门的超时分类仍按 P1 留待后续，本日不要求穷举异常类型。

提示：查 FastAPI 的请求体、HTTPException、TestClient；查 Pydantic 的 field_validator 或字符串约束。先写出自己的实现，卡住时再提交最小问题。

### 3. 离线测试与验收：40 分钟

新建 tests/test_meeting_api.py，使用 FastAPI TestClient 调用自己的接口。替换 API 模块使用的客户端工厂，返回一个假的客户端；假的 generate 返回你指定的 LLMResult。不读取真实密钥、不发送 Google 请求、不依赖免费额度。

测试覆盖：成功响应、缺少 text、空字符串、纯空白、FAILED、UNKNOWN、空回答。空回答可以参数化覆盖 None、空字符串和空白。

断言不只检查状态码：成功时检查 summary 等于模拟文字；无效输入时检查工厂未被调用；有效请求时检查 generate 的调用次数及传入的会议内容和整理规则。

运行：

```powershell
uv run --no-sync --offline pytest -v
```

这些标志阻止 uv 同步和下载依赖，但不能阻止测试代码联网；因此必须正确替换模型调用。若本地缺少依赖，先说明缺什么，不自动安装。

真实模型手动验证至多一次，有额度才做；没有额度时以离线测试验收接口行为，明确记录真实模型效果尚未重新验证。pytest 通过只证明所覆盖的行为，不能证明模型不会编造信息。
