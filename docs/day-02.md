## 2. 开发需求：命令行会议记录整理器

### 2.1 用户如何运行

从项目根目录运行自己实现的脚本：

~~~powershell
uv run --no-sync --offline python scripts/meeting_summary.py --text "今天讨论 Agent Workspace。小王周五前完成模型调用，小李周六前补聊天接口测试。前端展示方案尚未确定。"
~~~

--text 是你要实现的命令行参数，后面是一整段会议记录。可以查 Python 标准库 argparse 的用法，不需要为参数解析安装依赖。

--no-sync 避免 uv 自动同步依赖；--offline 限制 uv 下载依赖，不会禁止脚本调用 Gemini API。运行脚本时需要可访问模型服务的网络。

### 2.2 输入约定

- 用户输入：必填的 --text 字符串。本轮只接收一段命令行文本，不读文件或交互式多轮输入。
- 空字符串、全空白、未提供 --text：提示“会议记录不能为空”或清楚的参数用法错误，退出，不请求模型。
- 输入是整理对象；整理规则由你的程序构造，不能只把原文发出去而不说明希望模型做什么。
- 配置来自环境变量：GEMINI_API_KEY、LLM_MODEL。缺失或为空时提示缺少哪个配置并退出，不请求模型。
- LLM_MODEL 填写实际模型 ID，不含 models/ 前缀；它会传入 SDK 的 model 参数及 Interactions 请求体。

### 2.3 成功输出约定

终端展示三块中文内容：

1. 摘要：概括会议主题或结论。
2. 待办事项：列出行动、负责人、截止时间；原文缺少的信息写“未说明”，不要补造。
3. 待确认事项：列出明确未确定的内容；没有则写“无”。

上面样例的一种合格输出如下。措辞可以不同，但两条任务和未确定的信息应保留：

~~~text
摘要
讨论 Agent Workspace 的模型接入、接口测试和展示方案。

待办事项
- 完成模型调用；负责人：小王；截止时间：周五前
- 补聊天接口测试；负责人：小李；截止时间：周六前

待确认事项
- 前端展示方案尚未确定
~~~

“周五前”保留原文表达，不推算成日期。输出不能声称已经创建任务、发送消息或完成会议中的工作。今天只展示整理结果。

输出用普通文本即可，不要求 JSON Schema、数据库记录或逐字段解析模型生成的待办。程序必须从供应商响应中提取实际文字，不能把完整 HTTP 响应或固定样例当成结果。

### 2.4 错误行为

| 场景 | 用户应看到什么 | 是否请求模型 |
| --- | --- | --- |
| 未传 --text，或文本为空白 | 清楚的输入错误 | 否 |
| 缺失 / 空白 Key 或 Model ID | 明确缺少哪个配置，不能显示密钥 | 否 |
| 网络不可达或请求超时 | “模型服务连接失败”或“模型请求超时”等可理解提示 | 已尝试一次，不自动重试 |
| HTTP 非成功状态，如 400 / 403 / 404 / 429 | 必要的状态码与简短原因，不暴露鉴权信息 | 已尝试一次，不自动重试 |
| HTTP 成功但没有可用回答文字 | “模型未返回可用文本”，不当作正常摘要 | 已请求一次 |

成功退出码为 0，输入或调用失败时为非 0。今天不要求把错误映射成 FastAPI 的 422 / 502 / 504。

## 3. “构造 POST 请求”具体指什么

今天的执行链路：

~~~text
你在终端传入会议记录
    → Python 脚本校验输入并构造整理要求
    → 脚本向 Google 发一次 HTTPS POST
    → Google 返回模型响应 JSON
    → 脚本提取回答文本并显示
~~~

POST 是 HTTP 请求方法；在这里表示向模型服务提交一次生成请求。今天接收请求的是 Google 的服务。你的脚本在这条链路中是 HTTP 客户端；Day 1 的 FastAPI 在任务接口链路中是 HTTP 服务端。

2026-10-12 已核对学生使用的官方入口：https://ai.google.dev/gemini-api/docs?hl=zh-cn 。当前首页使用 Interactions API，并建议新项目采用；原始 generateContent 接口仍受支持。两者都属于 Google AI Studio / Gemini 原生 API，调用方法及字段不同。

已确认项目添加 google-genai、python-dotenv，环境中存在 Google SDK。因此本轮默认跟随学生的官方教程，通过 client.interactions.create 处理会议记录。SDK 是封装了 HTTP 请求的库，它替你完成下面的 POST、鉴权、JSON 编解码等细节。

若已经通过 client.models.generate_content 成功调用，也可用现有实现完成 Day 2 验收，不因接口选型要求重写；应同时使用对应的 contents 和 response.text，不能混入 Interactions 的字段。若按官网首页起步，则继续使用下面的 Interactions 流程。

第 3.1 节用于说明实际网络请求的含义，不要求你再手写一套 HTTP 客户端。如果你已经用 httpx 开始实现，也可以沿用；两种方式只选一种，完成同一输入输出要求。

### 3.1 地址、鉴权和请求体

Interactions 的固定请求地址；模型 ID 在请求体中指定：

~~~text
POST https://generativelanguage.googleapis.com/v1beta/interactions
~~~

请求头：

| 名称 | 值 |
| --- | --- |
| x-goog-api-key | 从 GEMINI_API_KEY 读取的实际值 |
| Content-Type | application/json |

请求体结构示意，model 替换为 LLM_MODEL 的实际值，input 的实际内容由你构造：

~~~json
{
  "model": "实际模型 ID",
  "input": "这里放你的整理要求，以及用户输入的会议记录",
  "store": false
}
~~~

Interactions 的 SDK 调用中，model 指定模型，input 接收整理要求和会议记录；返回对象使用 output_text 取得最终文本。可以查官方用法，不需要自行把 SDK 输入变成上述字典。这里也不用兼容接口的 messages / choices 格式。

今日每次处理独立会议记录，不传 previous_interaction_id，不启用 background 或工具。Interactions 可保存服务端状态；今天用 store=false 做无状态调用，对话状态管理放到后续模块。

设置明确网络超时，例如 30 秒。本地已安装 SDK 的 HttpOptions.timeout 单位为毫秒，因此对应值是 30000；HttpRetryOptions.attempts=1 表示只尝试一次，配置位于 HTTP 选项中。若使用 httpx，查 post 的 json 参数及以秒计的 timeout 参数。具体函数组织和整理要求由你实现。

### 3.2 如何读返回值

使用 Interactions SDK 时，先从返回的 interaction.output_text 读取文字，检查是否为空；需要学习完整结构时再查看步骤和使用量。

如果使用直接 HTTP 方式，Interactions 响应包含 steps，最终回答在 model_output 步骤的 content 中。只提取回答文字，不把模型思考或工具步骤当成摘要；没有可用文字时按错误场景处理。直接 HTTP 解析不是今天使用 SDK 的额外必做项。

可以打印必要的状态信息辅助调试，再把提取出的文字作为用户结果。Interactions 的 usage 可另外用于记录 Token 使用量；这是学习项，不是今日业务输出的必需字段。旧 generateContent 的 usageMetadata 属于另一种响应结构。

## 6. 算法摸底：1 小时

这是独立能力测量，保存你的尝试与用时，不必等会议程序完成后才处理环境阻塞。

- **两数之和，15 分钟独立尝试。** 给整数数组和目标值，返回两个不同位置的下标。样例：nums=[2,7,11,15]、target=9，结果为 [0,1]（顺序不限）；nums=[3,3]、target=6，必须使用两个不同位置。
- **无重复字符的最长子串，25 分钟独立尝试。** 输入字符串，返回最长无重复连续子串的长度。样例：“abcabcbb”→3；“bbbbb”→1；空字符串→0。
- **复盘，20 分钟。** 验证样例和边界，说明数据结构与复杂度。卡住时查最小提示，记录帮助内容和当前卡点。

如果使用题目平台，完整条件以题面为准。今天不要求两题都独立解出；会用记录决定后续训练的起点。

### 异步等待实验，约 30 分钟

场景：用本地等待模拟两次网络 I/O，观察等待能否重叠。A、B 两个操作分别打印开始、异步等待约 1 秒、打印结束。

比较：

1. 先等待 A 完成，再等待 B 完成，耗时应大约 2 秒。
2. 同时调度 A、B，再等待二者完成，耗时应大约 1 秒。

先写预测，再用计时验证；允许调度误差，不断言精确毫秒或并发操作唯一的打印顺序。查 asyncio.sleep、asyncio.gather、asyncio.run、time.perf_counter。实验不要请求真实模型。

提交两组耗时，并解释 await 等待时为什么事件循环能处理其他就绪任务，以及这个实验为什么不需要两个线程。
