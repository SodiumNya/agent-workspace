## 1. 总目标与起点

目标是在 2027 年 2 月实习前，具备 AI 应用 / Agent 开发及一部分通用后端岗位所需的独立编码、典型一面、项目答辩和问题排查能力。Agent Workspace 是训练和证明这些能力的主要项目。

个人条件：2028 届学生；计划前往杭州；目前预计可实习 2–3 个月；每天可学习 4–5 小时；有 Java + Vue Demo 经历，正在恢复 Python。

截至本次制定计划：

- Day 1 已通过此前的审查并关闭；此前最后一次测试记录为 8 项通过。本次保存计划没有重新运行测试。
- 仓库已推送至 GitHub：<https://github.com/SodiumNya/agent-workspace>。
- Day 1 验收范围为内存任务 CRUD、搜索及测试；之后新增的模型相关代码待提交审查，其他模块按完成证据登记，不推定已经实现。
- 当前依赖包含 FastAPI、Uvicorn、google-genai、python-dotenv；开发依赖包含 httpx、pytest。Gemini SDK 是学生自行添加的，本轮需求修订未安装依赖。
- 已选用 Google AI Studio 的 Gemini 原生 API，学生说明使用免费模型；具体 Model ID、配置及真实调用结果待提交验收。免费额度以所选模型和账户为准。

六周目标是可演示的核心版本，八周目标是可写进简历并接受追问的版本。完整面试准备持续至 2027 年 1 月。日期是排期估计，是否达标以验收结果为准。

## 3. 时间预算

每周安排 6 个学习日，第七天休息或补漏。16 周按每天 4–5 小时计算，理论投入为 384–480 小时。常规日按 4.5 小时安排；考试、课程及卡点造成的偏差，每两周复核一次。

| 内容 | 前 8 周 | 后 8 周 |
| --- | --- | --- |
| Agent 项目与相关实践 | 1 小时 45 分 | 30 分 |
| 开源代码阅读与对照 | 30 分 | 30 分 |
| 算法：学习、独立作答、复做 | 1 小时 | 1 小时 30 分 |
| Java 与后端基础 | 1 小时 | 1 小时 30 分 |
| 复盘、口头表达、简历与投递 | 15 分 | 30 分 |
| 合计 | 4 小时 30 分 | 4 小时 30 分 |

Java 与后端基础按天轮换，初期可每周各安排 3 天；根据摸底调整比例。周模拟面试和复盘占用上述时段，不额外增加晚间任务。

前 8 周项目实践预算约 84 小时，源码阅读约 24 小时，合计仍约 108 小时。阅读用于当期模块的设计与验证。发生延期时，优先削减扩展功能，保留算法和基础训练。最后四周保留补漏空间，不再预先排满新功能。单日按实际任务调整各项时长，总量保持 4–5 小时。

## 5. 项目范围

优先实现两个可验证的办公场景：

1. 文档问答带来源；没有可靠依据时能说明不足。
2. 从会议内容提取任务，经过用户确认后写入，能够查询和更新。

核心模块：模型调用、流式输出、工具调用、有限步数的 Agent Loop、基础 RAG、MySQL 持久化、运行状态、失败处理、执行记录、离线测试和小规模评测。

Redis 先用小实验学习 TTL、缓存与一致性；主项目有明确用途时再接入。MCP、复杂沙箱、多 Agent、大型前端、Kubernetes、分布式文件服务均属后续选项。

Java 实践优先恢复原有 Demo，补一条包含参数校验、数据库和测试的接口链路。若旧项目无法使用，另做一个范围相同的小型练习服务，不扩成第二个大型项目。

## 6. 面试能力验收

### 算法

- 预计覆盖 80–100 道代表题，并复做薄弱题；题量用于排课，不能单独代表掌握程度。
- 顺序：数组 / 哈希 / 字符串 → 双指针 / 滑动窗口 → 链表 / 栈队列 → 二分 → 树 / BFS / DFS → 堆 / 基础图 → 基础动态规划。
- 阶段目标：约 30–40 分钟独立完成常见中等题，说明时间和空间复杂度，并验证正常及边界输入。具体面试难度可能不同。
- 初期使用 Python；恢复 Java 后，定期用 Java 写已理解的代表题，检查语言表达能力，不要求每题双语重写。

### Java 与后端

- 独立使用集合、处理异常、编写服务与测试，能查文档解决 API 问题。
- 解释 HashMap、线程池、锁、线程安全及 JVM 基础；能用小实验验证部分结论。
- 独立写筛选、聚合、JOIN 等 SQL；解释索引、事务、隔离级别及常见慢查询排查思路。
- 解释 HTTP 请求过程、TCP 基础、进程线程、缓存一致性、超时、重复请求、消息消费和日志排障。
- 能用 Git、Linux 基本命令、Docker 完成项目运行和定位问题。

### AI 应用与项目答辩

- 解释模型生成调用信息、应用校验并执行工具、结果回传模型的全过程。
- 解释 Agent 的终止条件、状态与错误处理，讨论重复执行的后果。
- 区分检索失败、上下文不足、生成错误；通过评测判断 RAG 改动是否有效。
- 理解 Token / 上下文、Embedding、Attention 的基本作用，以及 RAG 与微调的区别。
- 用约 5 分钟讲清项目的问题、方案和结果，再接受约 20 分钟追问。
- 简历中的每项成果必须有代码、测试、日志或评测支撑；不虚构用户量、吞吐量或效果提升。

## 7. 导师协作方式

1. 先给任务目标、时间预算和验收标准。
2. 学生自行实现，卡住时先定位问题并给最小提示。
3. 必要时提供局部语法或库调用示例；完整业务实现仅在学生明确要求时给出。
4. 完成后审查代码、验证行为、追问设计理由。
5. 每周做一次小型口头或编码检查，每两周调整整体进度。
6. 每个学习日安排 30 分钟源码阅读；导师提前核对文件，给出阅读范围和关键问题。学生先解释，再对照自己的代码。每周复核一个设计决定和一个测试缺口，并说明是否需要调整原计划。具体安排见开源代码阅读计划。

测试通过是证据之一，HTTP 200 不能单独证明功能达标。每次验收同时检查功能、测试和解释能力。使用 AI 的部分需要能解释并验证。

Python 统一使用 uv：`uv add`、`uv add --dev`、`uv run`、`uv sync`。评审前检查测试是否下载依赖、访问外部服务或修改数据；真实模型调用由学生手动进行，自动化测试使用模拟响应。
