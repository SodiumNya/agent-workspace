# Web 后端与 Agent 工程知识缺口清单

更新日期：2026-10-12  
关联文件：[总计划](learning-plan.md) · [Day 2 任务单](day-02.md)

按学习依赖排列。每次选择一个小实验，预测、运行、解释，再记录尚未理解的问题。此清单可在其他学习对话中独立使用，不要求一次学完，也不阻塞全部项目开发。

这里的 P0 表示当前开发需要建立的基础理解，P1 表示后续模块前需要深入，P2 表示按岗位或实际需要学习。它们是学习优先级，不代表现有代码都存在同等级 Bug。

## 一、现在必须逐步理解

### 1. Python 对象、类型、函数调用 — P0

为什么学：Day 1 出现过 ID 类型不一致、`q.lower` 与 `q.lower()` 混淆；类型标注也需要与实际返回值一致。

关键问题：方法对象和调用结果有什么区别？类型标注会自动转换实际返回值吗？列表内的字典被另一个变量修改时，原列表会不会变化？

小实验：比较 `lower` 与 `lower()` 的值和类型；用两个引用指向同一个任务字典，修改其中一个并观察另一个。

### 2. HTTP 的客户端、服务端和请求响应 — P0

为什么学：任务 API 与模型 API 都通过 HTTP 交互，程序可以在不同链路中承担不同角色。

关键问题：请求头、路径参数、查询参数、JSON 请求体分别放什么？状态码能证明什么？成功响应应该验证哪些业务字段？

小实验：向现有任务接口发正常、缺字段、错误类型、空标题和不存在 ID 的请求，比较状态及 JSON。

### 3. FastAPI 的参数解析、校验、调用与序列化 — P0

为什么学：需要理解请求如何到达函数，Pydantic 如何校验，以及返回值如何变成响应。

关键问题：哪些错误发生在路由函数执行前？请求模型与普通字典有什么区别？HTTPException 如何变成 HTTP 响应？

小实验：在临时练习接口中记录函数是否进入，比较正常输入与触发校验错误的输入；观察返回字典如何变成 JSON。

### 4. 测试断言与测试隔离 — P0

为什么学：Day 1 曾出现测试通过却没有覆盖真实搜索错误的情况；每个测试会清空共享任务列表。

关键问题：只断言 200 会漏掉什么？测试初始状态与实际启动状态是否相同？为什么外部模型调用应该在自动化测试中模拟？

小实验：构造错误但仍返回 200 的响应，比较状态断言与精确内容断言；分别验证空列表和已有任务的搜索。

### 5. 进程、线程及内存边界 — P0

为什么学：Day 1 任务保存在全局列表里；部署多个进程后不能假定它们看到同一份任务。

关键问题：同进程的线程共享哪些状态？多个进程是否自动共享 Python 全局变量？服务重启后内存任务为什么消失？

小实验：分别在同进程线程和独立进程中修改一个列表，观察主程序的值；不启动多 worker 生产服务也可以验证概念。

### 6. 同步、异步、阻塞和 I/O — P0

为什么学：模型调用主要等待网络；需要区分函数的调用方式与执行时是否阻塞。

关键问题：等待网络时 CPU 在做什么？同步接口能否通过线程并发？CPU 密集工作与 I/O 等待适合相同方式吗？

小实验：比较两个延迟操作的依次执行和并发执行，先预测耗时。使用可控的本地等待，避免用付费模型做并发实验。

### 7. 协程、事件循环、await — P0

为什么学：建立异步代码的执行顺序模型，为异步 HTTP 客户端和流式响应做准备。

关键问题：调用 `async def` 得到的是什么？事件循环何时能切换其他任务？普通阻塞调用放进异步函数后会自动变成非阻塞吗？

小实验：比较依次 await 和 gather；再在临时异步练习中比较 `time.sleep` 与 `asyncio.sleep` 对其他任务的影响。

### 8. 线程池与 FastAPI 的 def / async def — P0

为什么学：Day 1 路由使用 `def`；理解框架如何调度，才能选择同步或异步库。

关键问题：普通 `def` 路由与 `async def` 路由分别在哪里执行？普通辅助函数会自动进入线程池吗？线程池满了会发生什么？

小实验：在临时接口中记录线程 ID，对比不同路由形式；用本地并发请求观察阻塞等待的影响。

### 9. 竞态、临界区、锁与 GIL — P0

为什么学：Day 1 删除接口先查找再删除；并发请求可能在两个步骤之间修改列表。

关键问题：单个操作安全能否保证多个操作组成的业务安全？GIL 为什么不能替代业务锁？线程锁与异步锁应该怎样选？

小实验：用可控同步点让两次删除都先找到同一任务，再执行删除，观察错误；比较保护完整操作前后的结果。不要只依赖随机压力碰运气。

## 二、Agent 阶段结合模块深入

### 10. HTTP 客户端、超时、取消和重试 — P1

依赖：第 2、6–8 项。为什么学：模型或工具变慢、失败时不能无限等待；盲目重试可能重复写任务。

关键问题：连接超时与读取超时有什么区别？哪些错误值得重试？客户端取消后服务端正在做的工作如何处理？

小实验：用本地模拟服务产生延迟、失败和断开，记录耗时与尝试次数；真实付费调用不用于自动故障测试。

### 11. 数据库、事务、状态与幂等 — P1

依赖：第 5、9、10 项。为什么学：任务需要跨重启保存，工具写入需要处理重复请求及并发修改。

关键问题：事务保护的边界是什么？唯一约束与应用锁分别解决什么？同一工具调用重试两次会不会创建两条任务？

小实验：用两条数据库连接并发更新同一记录；用唯一业务标识重复创建，验证最终条数和错误处理。

### 12. 流式输出、SSE 与连接生命周期 — P1

依赖：第 2、7、10 项。为什么学：流式响应要处理逐块读取、结束、断开和慢客户端。

关键问题：HTTP 数据块与完整业务消息有什么区别？客户端断开后还会继续生成吗？慢消费者会怎样影响内存和任务？

小实验：本地按固定间隔发送少量事件，记录收到时间；主动断开客户端，观察服务端清理和停止行为。

### 13. Function Calling、Agent Loop 和终止条件 — P1

依赖：第 3、10、11 项。为什么学：应用负责验证和执行工具，模型输出不能直接当作可信业务操作。

关键问题：谁执行工具？参数错误或未知工具怎样处理？模型反复调用工具时如何限制步数、时间和成本？

小实验：使用固定模型响应依次模拟正常工具、未知工具、错误参数和持续循环；验证执行记录及终止原因。

### 14. LLM 基础、Embedding 与 RAG — P1

依赖：模型调用和基本集合处理。为什么学：解释上下文限制、语义检索和文档问答失败，支持第三张截图的基础追问。

关键问题：Token 与文字数量是什么关系，Attention 大致做什么？Embedding 相似是否代表答案正确？如何区分检索失败与生成失败，RAG 与微调分别改变什么？

小实验：用固定短文档改变切块及检索数量，记录召回片段和回答；加入文档没有答案的问题，检查是否能明确说明依据不足。

### 15. 权限、确认和不可信内容 — P1

依赖：第 11、13、14 项。为什么学：办公 Agent 可以读取文档和写任务，需要控制访问范围及写入权限。

关键问题：权限检查应由模型还是应用完成？文档中的指令能否覆盖用户授权？确认后的写入如何绑定当前用户和实际参数？

小实验：构造越权工具参数及含恶意指令的文档，验证应用拒绝越权；确认前后改变写入参数，检查授权是否仍有效。

### 16. Trace、评测与故障定位 — P1

依赖：第 10–15 项。为什么学：从一次执行的记录中定位失败，并用可重复评测证明功能和效果。

关键问题：怎样关联模型请求、工具调用和最终结果？成功率、延迟、Token 成本如何定义？更换模型或切块后如何比较？

小实验：用固定输入集和模拟故障跑一次评测，保存版本、结果和失败分类，再改一项配置对比。

## 三、按岗位再学

### 17. Redis、消息队列、容器与平台扩展 — P1 / P2

Redis 的 TTL / 缓存一致性、消息确认 / 重投 / 幂等、Docker 基础运行属于后端准备的 P1；MCP、WebSocket 网关、复杂沙箱、Kubernetes 和分布式文件服务属于 P2 专项。

为什么学：前者支撑后端面试与项目运行，后者对应第二张截图的进一步平台能力。

关键问题：缓存过期或写库成功但删缓存失败会怎样？消息重投为什么需要幂等？协议工具接入、容器和安全执行沙箱各自解决什么问题？

小实验：分别做 TTL / 更新顺序实验、重复消费实验、容器启动与日志排查；后期按目标岗位选择一个专项，定义边界再实践。
